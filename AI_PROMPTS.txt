Related Requirement: HTL-20, HTL-22, HTL-23
Prompt:
Fix the root cause reported by P6: with @nestjs/mongoose 12 and Mongoose 9, @Prop({ type: Types.ObjectId })
becomes a Mixed field, so string ids from requests are stored as strings and later ObjectId lookups miss them
(new hotel rooms could not be updated or booked). Replace it with SchemaTypes.ObjectId in every schema and
verify the hotel flow.
How the output was used:
Changed the 9 affected schema files (audit log, session, hotel booking, hotel room, itinerary, itinerary day,
post, review, user) to type: SchemaTypes.ObjectId; no other code changed and no Types.ObjectId schema types
remain outside spec files. tsc passed, the app booted, and SchemaTypes was checked to be a runtime export of
mongoose. Then tested as the admin against the running API: create hotel (cairo, EG) 201, add room 201,
PATCH room availability for December 2026 200 (P6 reported 404 here before the fix),
GET /api/hotels/{id}/reservations 200.
Documents saved before the fix may still hold string ids and need a one-off migration.
